Project Overview: DeepStream License Plate and NZ Vehicle Recognition Pipeline

1. System and Environment

Camera / RTSP device:
- Jetson Nano at 192.168.0.137.
- ZED camera is captured by /home/coen/stream.py.
- 1920x1080, 30 FPS H.264 RTSP/TCP stream.
- Stream URL: rtsp://192.168.0.137:8554/zed_stream.

Inference device:
- NVIDIA Jetson AGX Xavier 16 GB.
- JetPack 5.1.6, DeepStream 6.3, TensorRT 8.5, CUDA 11.4.
- Python 3.8 with DeepStream Python bindings (pyds).
- RapidOCR 1.4.4 using ONNX Runtime 1.19.2.

Cloud logging:
- Confirmed plates are posted to the existing Convex uplink.

2. AI Pipeline

Pipeline:
RTSP -> H.264 decode -> nvstreammux -> YOLO -> NvDCF tracker ->
LPDNet -> NZ-50 vehicle classifier -> RGBA convert -> OSD -> nv3dsink

A. YOLO primary detector
- DeepStream component ID: 1.
- Detects the 80 COCO classes.
- Car class ID 2 is the input to the NZ-50 classifier.
- Uses the existing custom YOLO DeepStream parser and FP16 engine.

B. NvDCF tracker
- Assigns stable object IDs before either secondary inference stage.
- The vehicle recognizer keeps temporal state by this tracker ID.

C. LPDNet secondary detector
- DeepStream component ID: 2.
- Locates plates within COCO car and truck objects.
- Uses the existing INT8 TensorRT engine.

D. NZ-50 vehicle-family classifier
- DeepStream component ID: 3.
- EfficientNet-B4 trained on the public VMMRdb make/model/year dataset.
- The 8,949 source outputs are grouped into 50 common NZ model families.
- Regional aliases such as Mazda3/Axela and Fit/Jazz share one output.
- Input: RGB 3x380x380.
- Output: 50 grouped probabilities named family_probabilities.
- Runs asynchronously on tracked COCO car objects.
- Re-infers each vehicle every 30 frames.
- Requires three matching, above-threshold inference windows.
- Uses per-family application thresholds; uncertain vehicles remain Unknown.

E. RapidOCR
- Runs from the Python pad probe on plate crops produced by LPDNet.
- OCR is throttled per tracked plate.
- A plate requires three matching reads at confidence >= 0.85.

3. Runtime Files

new.py:
- Builds and runs the complete pipeline.
- Reads DeepStream classifier metadata.
- Preserves plate OCR and Convex logging.
- Updates primary vehicle OSD labels with stable model-family results.

vehicle_recognition.py:
- Pure-Python recognition state machine.
- Applies thresholds, temporal consensus, relabel hysteresis and expiry.
- Writes rotating JSONL confirmation events.

vehicle_model_manifest.json:
- Defines the 50 families, source-class selectors, thresholds and model version.
- Is the source of truth for the runtime and export tool.

vehicle_model_labels.txt:
- DeepStream label file in the exact manifest output order.

config_infer_vehicle_model.txt:
- DeepStream secondary classifier configuration.
- Points to /home/hero/vehicle_recognition/vmmr_nz50.onnx.
- The FP16 TensorRT engine is built on the AGX, never copied from a PC.

tools/export_vmmr_family_onnx.py:
- Verifies the pinned source checkpoint checksum.
- Rejects missing/overlapping family mappings.
- Exports a self-contained opset-13 ONNX model.

tools/validate_vehicle_family_model.py:
- Checks ONNX structure, shape and probability output.
- Optionally calibrates thresholds from a path,label CSV dataset.

~/xavier_received_images/:
- Confirmed license plate crops.
- vehicle_recognition.jsonl and up to three 5 MB rotated backups.

4. Vehicle Recognition Events

One JSON object is written for the first confirmed result on a track:
- schemaVersion
- event
- UTC timestamp
- trackerId
- make
- model
- label
- confidence
- modelVersion
- bounding box

Unknown results are not written as confirmed recognition events.

5. Operational Notes

- Start the Nano stream before starting new.py on the AGX.
- AGX start command: DISPLAY=:0 python3 new.py
- The script resolves configuration files relative to new.py.
- Required runtime assets are checked before the GStreamer pipeline starts.
- The existing 15-second no-frame watchdog remains active.
- HTTP requests and plate image writes remain off the GStreamer thread.
- The existing NVIDIA VehicleMakeNet files are retained as backups but are not
  loaded, because NZ-50 supplies make and model from one consistent classifier.
- Do not commit checkpoints, ONNX models, TensorRT engines, datasets or JSONL
  runtime logs.
